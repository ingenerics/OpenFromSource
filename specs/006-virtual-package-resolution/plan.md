# Implementation Plan: Virtual Package Resolution

**Branch**: `006-virtual-package-resolution` | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/006-virtual-package-resolution/spec.md`

## Summary

Add `provides` and `virtual_resolutions` tables to the database. The `provides` table captures `Provides` fields from Packages.gz during init using a natural key (no FK to binaries). The `virtual_resolutions` table records which real binary was selected for each virtual package name during `add`, with a FK to `binaries(id)`. The resolver is extended to detect virtual dependency references, query provides for candidates, select deterministically, and persist the choice.

## Technical Context

**Language/Version**: Python 3.13.x (Debian Trixie LTS default)

**Database**: SQLite 3.x — schema version 1 (no bump during development). Add `provides` and `virtual_resolutions` tables. Existing tables unchanged.

**Primary Dependencies**: python-debian (deb822), sqlite3 (stdlib)

**Existing Architecture**:
- `database.py` has 5 tables (packages, binaries, sources, binary_to_source, source_build_deps) with release/component/status columns from spec 005
- `index_loader.py` parses Packages.gz/Sources.gz via deb822
- `BinaryPackage` model has `release` and `component` fields from spec 005
- `initializer.py` handles cache directory creation during init
- `resolver.py` has upsert_binary/upsert_source, dependency resolution loop

**What needs to change**:
1. **database.py**: Add `provides` and `virtual_resolutions` tables
2. **initializer.py**: Add `populate_provides_table()` — parses provides_raw from each BinaryPackage in the repository index, inserts natural-key rows into provides table
3. **init.py**: Call populate_provides_table after loading the index
4. **resolver.py**: Extend `_resolve_one()` to detect virtual dependencies, check virtual_resolutions, query provides, select provider, create binaries entry, record resolution
5. **show.py**: Add provides and virtual_resolutions to known tables
6. **index_loader.py**: May need minor adjustments for provides_raw field parsing

**Performance Goals**: Virtual lookups via indexed `virtual_name` column — O(log n). No new performance targets beyond existing constitution targets.

**Constraints**: DB as source of truth; provides populated during init, not add; virtual_resolutions persist across add invocations.
